# Anarchy Online ItemsExtractor (Python)

A Python port of the Budabot ItemsExtractor for Anarchy Online resource databases (`ResourceDatabase.idx`, `ResourceDatabase.dat*`).

## Features
- Pure Python 3 using standard library modules (`sqlite3`, `struct`, `configparser`, `argparse`, `logging`).
- High throughput in-memory buffered index reader and item extraction.
- In-memory SQLite matching and pairing engine.
- Regenerates the items module's SQL files in `modules/standard/items/sql` and the specials module's `weapon_attributes.sql`:
  - `aodb.sql`
  - `item_buffs.sql`
  - `item_types.sql`
  - `skills.sql`: every stat in `item_buffs` that has a skill name in the game's `text.mdb` (category 2003), with common names from the `[skill_common_names]` section of `config/extractor.cfg`.
    - Buffed stats with no skill name are left out and logged.
    - A stat in `[skill_common_names]` that is not in `skills.sql` stops extraction.
- Regenerates `modules/standard/tower/tower_site_bounds.sql` from the game's land control districts.
  - Each district is matched to a `tower_site.sql` row by playfield and centre (`x_coord`, `y_coord`); the row supplies the site number.
  - The district's name and QL range must equal the row's, and every `tower_site.sql` row must match a district, otherwise extraction stops.
  - Land control districts with no `tower_site.sql` row are skipped and logged as warnings.
- Regenerates the implant module's `ImplantMatrix.sql`, `ClusterImplantMap.sql`, `implant_requirements.sql`, `Symbiant.sql`, `SymbiantAbilityMatrix.sql`, `SymbiantClusterMatrix.sql` and `SymbiantProfessionMatrix.sql` from the game's implant and symbiant items.
  - The tables use the game's ids for slots, abilities, professions and clusters; `ImplantType.sql`, `Ability.sql`, `Profession.sql` and `Cluster.sql` list the valid ones.
  - The `[implant_excluded_items]` section of `config/extractor.cfg` lists implant items to leave out.
  - A slot, ability, profession or cluster stat missing from those tables, or an implant that doesn't fit the expected QL 1/200/201/300 set, stops extraction.
  - `Symbiant.ID` is the symbiant's item id.
- Regenerates the perks module's `perks.sql` from the game's SL perks (record type 1000036), one item per perk level.
  - Each perk's levels follow the record's link to the previous level; a level's minimum character level and professions come from its item's requirements.
  - Buffs are the item's stat modifiers while worn, named with the game's short skill names from `text.mdb` (category 2003).
  - A perk whose levels allow different professions is logged as a warning; `perk_prof` lists the professions of every level.
  - An unexpected requirement, a broken level chain or a buffed stat with no skill name stops extraction.
- Regenerates the helpbot module's `research.sql` from the game's LE research lines (record type 1000036).
  - Each research level's SK cost and character level requirement must be the same in every profession research line, otherwise extraction stops.
  - Research lines with no profession, such as Apotheosis, are skipped and logged.
- Regenerates the helpbot module's `dyna.sql` from the game's districts whose names mention a dynacamp.
  - Label and mob come from the district name, the level range from the district's NPC levels and the coordinates from its centre.
  - The `[dyna_mob_names]` section of `config/extractor.cfg` renames mobs the game spells differently; a name there that no district uses stops extraction.
- Regenerates the trickle module's `trickle.sql` from the game's trickle records (record type 1000204) and skills-window group names (`text.mdb` category 10010).
  - The `[trickle_groups]` section of `config/extractor.cfg` lists each group's skills in display order; a group the game doesn't have, such as the ACs, uses its name as the key.
  - A listed stat with no trickle record or skill name, or listed twice, stops extraction; trickle records in no group are logged.
- Regenerates the alien module's `leprocs.sql` from the game's LE research lines (record type 1000036).
  - A research level's item grants an action; the action's nano holds the proc's chance, offensive or defensive trigger and effect nano.
  - Modifiers describe the effect nano and the nanos it casts, using the game's short skill names (`text.mdb` category 2003) and nano strain names (category 2009).
  - Stats that differ only by damage type and share an amount are shown once, by their name without the damage type; the `[leproc_stat_groups]` section of `config/extractor.cfg` names other stat sets shown once when all change by the same amount.
  - A spell function, target or stat the extractor can't describe, or a proc nano whose description doesn't name its action type, stops extraction.
- Every generated file starts with a `-- Generated by items_extractor` comment.
- Dual console and file logging (`extractor.log`) enabled by default at `DEBUG` level for post-run analysis.

## Requirements
- Python 3.8+ (no third-party pip dependencies required)

## Usage

### Local Python
```cmd
python extract.py -d "C:\Funcom\Anarchy Online"
```

### Docker
```cmd
docker run --rm -v "C:\Funcom\Anarchy Online:/ao:ro" -v "%cd%":/app -w /app python:3 python extract.py -d /ao
```

### Items Options
- `--items-dir <path>`: Directory where `aodb.sql`, `item_buffs.sql`, `item_types.sql` and `skills.sql` are written (default: `../modules/standard/items/sql`).
- `--specials-dir <path>`: Directory where `weapon_attributes.sql` is written (default: `../modules/standard/specials`).

### Tower Site Options
- `-t`, `--tower-dir <path>`: Directory containing `tower_site.sql`, where `tower_site_bounds.sql` is written (default: `../modules/standard/tower`).

### Implant Options
- `-i`, `--implant-dir <path>`: Directory where the implant SQL files are written (default: `../modules/standard/implant/sql`).

### Perks Options
- `-p`, `--perks-dir <path>`: Directory where `perks.sql` is written (default: `../modules/standard/perks`).

### Helpbot Options
- `--helpbot-dir <path>`: Directory where `research.sql` and `dyna.sql` are written (default: `../modules/standard/helpbot`).

### Trickle Options
- `--trickle-dir <path>`: Directory where `trickle.sql` is written (default: `../modules/standard/trickle`).

### Alien Options
- `--alien-dir <path>`: Directory where `leprocs.sql` is written (default: `../modules/standard/alien`).

### Logging Options
- Default log file is `extractor.log` in the current directory.
- `-l`, `--log-file <path>`: Custom log file path.
- `--no-log-file`: Disable writing log to disk.
- `--log-level {DEBUG,INFO,WARNING,ERROR,CRITICAL}`: Set logging level (default: `DEBUG`).
- `-q`, `--quiet`: Set logging level to `INFO`.
- `-v`, `--verbose`: Enable debug logging (default).

## Checks
`check.py` checks the bot's hand-maintained module data against the game and the generated item tables, without writing any files.
```cmd
python check.py -d "C:\Funcom\Anarchy Online"
```
- `raid_loot.sql`: each row's high id, QL and name must match an item in `aodb.sql`; repeated rows are reported.
- `boss_loot.sql`: each row needs a boss in `boss.sql` and an item named in `aodb.sql`; repeated rows and boss ids are reported.
- Recipes: every item a recipe links, lists or details must exist in the game, and every step must use listed items. Text steps, and listed placeholders without an item id, are skipped.
- `EffectTypeMatrix.sql` must hold the shining cluster values of each effect type's clusters at QL 1, 200, 201 and 300, and each effect in `EffectValue.sql` must match the cluster values of some effect type.
- `whompah_cities.sql`: the routes in `whompah_cities_rel` must be the routes the game's whompahs make. Cities whose zone names a game playfield are matched to that playfield's whompahs, the rest to whichever whompahs give the fewest differences.
- `nanos.sql`: each row's id must be a game crystal that uploads a nano, with the row's QL and name, and its professions in `nanos_professions.sql` must be every profession the crystal allows (`General` when it allows any). A box that uploads one nano per profession is listed once per nano as `<box name> [<nano name>]`, with that upload's professions; repeated rows and professions of unknown nanos are reported.
- Each problem is logged with its file and line; the exit code is 1 when any problem is found.
- `run-check-docker.bat` runs the checks in the tyrbot Docker image.
- `-c`, `--config <path>`: Config directory (default: `./config`).
- `-m`, `--modules-dir <path>`: Standard modules directory (default: `../modules/standard`).
